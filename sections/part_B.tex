\section{Part 2: Boolean GPT }

\subsection{2.1: Build an appropriate dataset}
Similar to the math model, the Boolean GPT model's dataset was generated deterministically via a python script. This script creates unique boolean expressions and their respective solutions, ensuring ground truth labels are completely accurate. The dataset includes boolean logical operations such as AND, OR, NOT, and XOR, with two levels of complexity selected via the `--basic` and `--advanced` flags. Similar to before, the basic dataset was just used to confirm the model and evaluation scripts were functional, while the advanced dataset was used for final evaluation.

\subsubsection{Issues with dataset}
Due to the nature of Boolean logic, the number of unique expressions is much smaller than in the previous math arithmetic. There are only two operands, True and False, and a limited set of operators (AND, OR, XOR, NOT), which means that all can be exhaustively enumerated with relatively few samples. As a result, the dataset contains only a few hundred unique expressions. 

Increasing the dataset size would therefore only possible by scaling the complexity of expressions.

Finally, because the model is character-level, accuracy is sequence-based rather than label-based. The model must generate the exact target string character-by-character after seeing the prompt up to the equals sign, so even a logically correct intention that produces an incorrect sequence (e.g., wrong spelling, extra whitespace, or partial tokens) is treated as incorrect. This is overcome in the following adaptations section.

\subsection{2.2: Define appropriate evaluation metrics}
Unlike math arithmetic, boolean logic has either a True of False output, meaning this task can be treated as a binary classification problem. 

The primary metric is accuracy, defined as the proportion of test expressions for which the model's generated output matches the ground-truth Boolean value. This is the most appropriate headline metric for Boolean logic, as any deviation from the correct value represents a complete logical failure rather than a partial error. Because the output space is binary and unambiguous, exact match accuracy directly measures task success

To gain more detailed insight into model behaviour, operator-wise accuracy is also reported. This metric breaks exact match accuracy down by the dominant logical operator appearing in each expression (AND, OR, XOR, NOT). This analysis is particularly important for Boolean logic, as different operators have fundamentally different properties. In particular, XOR is not linearly separable and is known to be more difficult for simple models to learn. Operator-wise accuracy therefore helps identify whether the model has learned general logical reasoning or is relying on shallow heuristics that work only for certain operators.

In addition, standard classification metrics derived from the confusion matrix are computed: precision, recall, and F1 score. These metrics complement accuracy by exposing potential biases in the model's predictions. For example, a model that defaults to predicting False on difficult expressions could achieve deceptively high accuracy if the dataset is balanced, but would exhibit poor recall for the True class. Precision, recall, and F1 score make such failure modes explicit and ensure that performance is not being overstated by a single aggregate metric.

Finally, to provide further granularity to the accuracy metric, operation-wise accuracy was also recorded. This provides the accuracy values for expressions with either one or two operators. 

Together, these metrics provide a rigorous and interpretable evaluation framework for assessing the Boolean GPT model's performance.

\subsection{2.4: Explore results for a range of arithmetic options}

This section evaluates the Boolean GPT model’s ability to learn and apply different logical operators, using quantitative results and representative examples. Evaluation on 49 unseen test expressions yields an overall exact match accuracy of 75.51\%, with a validity rate of 100\%, indicating that the model consistently generates well-formed Boolean outputs despite operating at the character level.

Operator-wise results show clear variation in difficulty. OR is learned perfectly, achieving 100\% accuracy, with expressions such as 1 | 0=1 and (0 | 0) | 0=0 always evaluated correctly. This reflects the simplicity and monotonic structure of OR, which is easy for the model to capture even in chained expressions. AND also performs well, with an accuracy of 76.92\%, and is generally correct in cases like 1 \& 0 \& 0=0. Errors typically arise when AND is combined with other operators, indicating challenges with composition rather than misunderstanding AND itself.

NOT is also solved perfectly in this evaluation, but it is under-represented, appearing in only a single test case. While simple negation such as ! 0=1 is handled correctly, this result should be interpreted cautiously due to the small sample size.

XOR is the weakest operator, with an accuracy of 68.97\%. Many errors involve chained or nested XOR expressions, such as $1 \text{\textasciicircum} 1 \text{\textasciicircum} 1$ or $0 \text{\textasciicircum} (1 \text{\textasciicircum} 0)$, reflecting the non-linearly separable nature of XOR and the need to track parity across operands. This makes XOR substantially harder than AND or OR for the model.

Expression complexity further explains these results. All single-operator expressions are solved correctly, while accuracy drops to 73.33\% for expressions containing two operators. This indicates that the main failure mode is compositional reasoning, particularly when multiple operators interact.

The character error rate of 0.2449 reflects incorrect final truth values rather than malformed outputs, as Boolean outputs are short. Precision, recall, and F1 score are all 0.7391, indicating balanced performance across True and False classes. Overall, the model reliably learns simple Boolean operators, but struggles with XOR and with deeper compositional structure, highlighting the limits of character-level reasoning for non-linear logical operations.
